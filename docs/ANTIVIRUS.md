# Unsigned Binary Policy, Verification & Antivirus Guidance (`docs/ANTIVIRUS.md`)

Radpa binaries distributed via GitHub Releases are **open-source and NOT Authenticode-signed** (no commercial code-signing certificate is purchased).

## 1. Why SmartScreen or AV May Flag New Unsigned Releases
Windows Defender SmartScreen tracks code-signing reputation and download prevalence. Newly published single-file `.NET` binaries without a paid EV/OV certificate may temporarily show:
- *"Windows protected your PC"* (SmartScreen), or
- Heuristic alerts in third-party AV engines (especially `Radpa.NetCollector.exe` because it uses Windows ETW kernel-network tracing).

---

## 2. How to Verify Every Release Before Running
Every official tag build (`v*.*.*`) in `.github/workflows/release.yml` produces:
1. **`SHA256SUMS.txt`** containing lowercase SHA-256 digests of all `.exe` files.
   Verify locally in PowerShell:
   ```powershell
   Get-FileHash .\Radpa-win-x64.exe -Algorithm SHA256
   ```
2. **SLSA / GitHub Build Provenance Attestation** generated by `actions/attest-build-provenance`, cryptographically linking each release binary back to the exact GitHub Actions workflow run and commit hash. You can verify it with GitHub CLI (`gh`):
   ```powershell
   gh attestation verify .\Radpa-win-x64.exe --repo MHKarami97/Radpa
   ```

---

## 3. Clean PE & Build Hygiene in This Repository
We intentionally follow Microsoft's guidance to minimize false positives:
- Full PE version/company/product/copyright metadata embedded in `Directory.Build.props`.
- Application manifests (`app.manifest`) set `requestedExecutionLevel level="asInvoker"` cleanly—never hidden elevation or obfuscators/packers (`UPX`, etc.).
- Source code, CI build scripts, and tests are 100% public and reproducible (`ContinuousIntegrationBuild=true`, `Deterministic=true`).

---

## 4. Submitting a False Positive to Microsoft Security Intelligence
If Microsoft Defender quarantines or flags an official Radpa release binary:
1. Verify the SHA-256 hash matches `SHA256SUMS.txt` on the official GitHub Release page.
2. Open the Microsoft Security Intelligence submission portal:
   `https://www.microsoft.com/en-us/wdsi/filesubmission`
3. Sign in (or submit anonymously as a Home user / Software developer).
4. Upload the `.exe` binary (or link the GitHub Release URL), choose **"Incorrectly detected as malware/malicious (false positive)"**, enter **"Radpa (open-source Windows local usage monitor)"**, and submit.
5. Usually Microsoft Defender updates cloud/definition signatures within 24–48 hours; run `Update-MpSignature` in PowerShell once approved.
